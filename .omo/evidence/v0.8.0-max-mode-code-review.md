### P1 (real bug / degraded UX with workaround)

- **HIGH-1 — Adopting the winner's conversation writes the seeded candidate prompt into the
  user's session transcript.** `lib/par_code_repl.ml:395` (Answer) and `:412` (Execute) set
  `conv := Some winner.conversation`. The winner's conversation contains the user message as
  `candidate_prompt` — "Your assigned angle for this answer: ... User request: ..." —
  instead of the user's actual message (max_mode.ml:39-42 builds that wrapper, and
  `Runtime.invoke` appends it as the user turn). Consequences: the persisted session, the
  checkpoint summary, memory extraction, and any resumed session all show the seed wrapper
  as the user's message; the original wording is lost from history. Minimal fix: after
  picking the winner, rewrite the appended user message in the adopted conversation back to
  the original `message` (or append the winner's assistant reply onto the original
  conversation instead of adopting the candidate's transcript).
