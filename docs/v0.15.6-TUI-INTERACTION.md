# TUI 交互升级计划（v0.15.6 起）

> 冻结于 2026-11-22。本文件是这一轮交互工作的验收基线：阶段、判据、回滚都写在这里，实施按阶段推进。
> 调研依据见记忆库 `reference/par-code/opencode-tui-borrowables.md`（上游 opencode `packages/tui` 源码阅读，只读）。

## 目标

让全屏界面在「读、抄、插话、批改」四件事上不输成熟工具：

1. 转写区的文字可以用鼠标/手指选中，松开即复制到系统剪贴板。
2. 回合运行中可以继续输入并回车插话（steer）：消息在本步工具批次结束后进入对话；若回合已结束，消息作为下一轮输入自动开始。
3. 模型改文件前先给出一屏 unified diff 预览，允许 / 本次会话内一律允许 / 拒绝。

## 非目标

- 不做内置终端面板、会话标签页、多工作区、插件槽（上一轮调研已判定收益低）。
- 不改键盘编辑模型（多行输入、历史、Ctrl-R 搜索、Tab 补全保持现状）。
- 不做主题系统与命令面板（另立计划）。
- 不做鼠标框选以外的复制方式（不做 opencode 的 cell/line 多级选择行为）。

## 已确认的 SDK 事实（PAR 0.17.3-beta.20261118）

- **steer 可用**：`Par.Runtime.steer : runtime -> string -> unit`，消息进 `Steering_queue`；引擎在每轮循环开始（含工具批次之后）用 `drain_into_conv` 把队列里的消息作为 `User` 消息追加进对话（`lib/core/engine.ml:787`、`:830-840`）。配套 `drain_steering` / `has_pending_steering`（`lib/core/runtime.mli:707-715`）。
  - 意味着：插话在「下一次模型调用前」生效，不会打断正在流式返回的当前回复；如果回合在插话前结束，消息仍留在队列里，由 par-code 自己取出来作为下一轮输入。
- **工具钩子看得到完整参数**：`Hook.tool_call_context = { tool_name; tool_call_id; input : Yojson.Safe.t; has_ui : bool }`，返回 `Allow | Block {reason} | Modify {input}`（`lib/core/hook.ml:11-18`）。引擎在调用工具处理器前跑完这些钩子（`lib/core/engine.ml:1111`），因此「改文件前弹 diff 批准」不需要改 SDK。
- `edit` 入参是 `{path, edits:[{old,new}]}`；`write` 是 `{path, content, create_dirs}`；`apply_patch` 是 `{patch, dry_run}`，patch 本身就是 unified diff（`lib/tools/builtin_tools.ml:1197-1230, 1329+`）。

## 阶段 1 —— 选中与复制

- **选区模型**：转写区按「绝对行号 + 显示列」记录锚点与焦点；绘制时把选中区间内的字符改成反色。行号基于当前列宽下的折行结果（和改字号重排一致）。
- **手势**：
  - 桌面：`Shift+拖拽` 选字，松开即复制。
  - 手机/无 Shift：`Ctrl-X` 切换「选择模式」（状态栏提示「select · drag to copy · Ctrl-X exit」），模式内拖拽选字、松开复制，`Esc` 或再次 `Ctrl-X` 退出。选择模式下滚轮仍滚动。
- **剪贴板**：写 OSC 52 转义（base64），由终端模拟器自己落到系统剪贴板（Termux 支持这一序列）。复制后在转写区追加一行 `✓ copied N characters`。
- **判据**：反色高亮跟手；跨行选择文本按行拼接、行尾不带填充空格；中文/emoji 的列宽不丢字；终端不支持 OSC 52 时至少给出提示，不吞键。
- **落点**：`par_code_screen.ml`（事件、绘制、状态）、新 `par_code_clipboard.ml`（OSC 52 + base64 + 外部命令）。
- **回滚**：移除选区渲染与鼠标分支；剪贴板模块不参与其它路径。

## 阶段 2 —— 运行中排队并自动投递

- 回合运行期间输入行保持可编辑；`Enter` 把消息放进屏幕自己的排队区（转写区立即回显），不再直接交给运行时。
- composer 上方是排队 dock：最多显示两条待发消息预览，超过时显示数量；`Ctrl-U` 撤回最新一条（输入为空时才生效，否则仍是删行首）。
- 投递时机：每个工具事件（`Tool_invoked` / `Tool_completed` / `Tool_failed`）把排队消息交给 `Runtime.steer`，引擎在下一轮循环开头把它作为用户消息并入对话；回合结束仍有剩余时，REPL 取出发起一轮 follow-up，输入不丢。
- **判据**：真跑排两条、`Ctrl-U` 撤回一条，剩余一条在回合结束后被模型回答，被撤回的那条不得出现在会话记录里；空输入时 Esc 仍是中断。
- **回滚**：去掉排队 dock 与 `turn_active` 输入路由，运行期按键恢复为只认 Esc/滚动。

## 阶段 3 —— 改文件前的 diff 审批

- 新配置 `edit_approval`：`"ask"`（默认）| `"auto_project"` | `"always"`，语义与 `bash_approval` 对齐；`par config set edit_approval always` 可关闭。
- 一个 `tool_call_hook`（在既有权限 deny 之后）覆盖 `write` / `edit` / `apply_patch`：
  - 预览内容：`write` 用现有文件内容与 `content` 做 diff（新文件显示 `new file`）；`edit` 按 `old`/`new` 在内存中套用到现有内容后做 diff（匹配不到时明确标注）；`apply_patch` 直接展示 patch 文本里的 `@@` / `+` / `-` 行。
  - 弹窗：标题 `Edit <path>?`，正文为 diff（红删绿增、青色 hunk 头，带上下文 3 行，超出正文高度时折叠成 `… N more lines`），选项 `y allow once` / `a allow for this session` / `n deny`。拒绝返回 `Block {reason}`，工具结果变成 `Permission_denied`。
  - `always` 不弹；`auto_project` 对工作区外路径弹（内置工具本来就会拒绝工作区外路径，因此实际等价于不弹；保留字段是为了和 bash 策略一致）。
- **判据**：单测覆盖 diff 计算（新增/删除/修改/多 hunk/未匹配）、策略判定、`new file`；真跑让模型改一个临时文件，弹窗出现且显示正确 diff，选 `n` 时文件未变、选 `y` 时写入。
- **回滚**：`par config set edit_approval always` 即恢复现状；代码侧删掉该 hook。

## 依赖与顺序

阶段 1 的折行/渲染改造是阶段 3 弹窗排版的基础（同一套 `wrap_runs` 与样式）；阶段 2 独立，但共用同一份输入状态改造。按 1 → 2 → 3 推进。

## 验收总则

- `dune build` 退出码 0，全部 Alcotest 套件通过（含新增纯函数测试）。
- proot + tmux 真跑真实 provider：选择复制看得到反色与复制提示；运行中排队可看可撤，剩余消息回合结束自动投递；改文件弹 diff 并能批准/拒绝。
- 终端尺寸与字号变化后选区坐标不崩（与 v0.15.4 的重排共用缓存）。
