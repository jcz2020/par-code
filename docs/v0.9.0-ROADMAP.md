# v0.9.0 ROADMAP — Self-improvement（/dream + /distill + 自定义 slash 命令）

> 状态：**已确认**（2026-11-03，用户在两项范围中选 1：self-improvement）。W0–W5 按 §7 推进；版本号在发布前保持 0.8.2。
> 前置：v0.8.2（已发布，2026-11-03）；PAR SDK `v0.12.0-beta.20261023`。
> 一句话：把重复工作流沉淀成可复用的 skill/命令，把记忆整理成更短更准的索引。

---

## 0. 主题与范围

**一句话**：agent 不再每次都从零开始——用户可以把反复出现的流程固化成 `/命令`，把散落的记忆整理成一份更短、更准的索引。

| 维度 | 决定 |
|---|---|
| 版本类型 | MINOR（v0.9.0），纯增量；无破坏性 API 变更 |
| 核心用户价值 | *"It turns my repeated workflows into reusable skills."*（README roadmap 行） |
| **做** | skill 发现/注册（W0）、自定义 slash 命令 + `/skills`（W1）、`/distill`（W2）、`/dream`（W3）、测试（W4）、文档与发布（W5） |
| **不做** | ① **执行级 best-of-N**（每候选一个 worktree、胜者 diff 回灌）→ 推迟到 v0.10+，退役条件见 §3 决策 1；② 远程 skill URL / 多来源 skill（v0.11.0 的 Ecosystem）；③ 自动安装、skill 市场、自动改用户文件；④ 自动删除记忆（`/dream` 默认 dry-run）；⑤ workflow engine（v0.10.0 Compose）；⑥ **任何 PAR SDK 改动**——缺口只记录 feedback |
| 范围决策记录 | 见 §3；实施时同步 README roadmap 行、CHANGES、STRATEGY、DECISIONS |

**为什么现在做**：v0.8.2 已收口 v0.8.0 审计的 P0/P1/P2，知识库刷新也已合并；README/STRATEGY 把 v0.9.0 公开定位为 self-improvement。继续拖会让"重复工作流"每次仍靠模型临场发挥，也让 `par-code-memory` 的条目只增不减。

## 1. 背景与现状（v0.8.2 核读）

### 1.1 记忆层

- `Par_code_memory` 的 kind：`Preference | Convention | Insight | Gotcha | Task_map`；已有 `add` / `forget` / `list` / `recall` / `render_index` / `export_markdown` / `prune_stale(_dry_run)`。
- **缺** `update`：SDK `Sqlite_memory.update` 已存在（`lib/memory/sqlite_memory.mli:45`，接收完整 `Memory_object.memory_object`），但 par-code 包装层没有暴露。`/dream` 的"合并/改写"需要它；否则只能 forget+add，丢掉 id、usage_count 与 created_at。
- 抽取器 `Par_code_extractor` 已有质量门与去重（`deduplicate`）；`/dream` 可以复用其 prompt 思路，但目标不同：抽取器是"从对话中加新条目"，`/dream` 是"对已有条目做合并/收敛/剪枝"。

### 1.2 Skill 层

- SDK 自带 `Skill_loader`：扫描 `~/.par/skills/<id>/skill.md` 与 `./.par/skills/<id>/skill.md`（项目优先，同 id 项目覆盖用户），解析 frontmatter 为 `Types.skill_descriptor`：
  - `schema_version`（必须 1）、`id`、`name`、`description`（≤1024）、`trigger`（Auto / Manual / Keyword）、`tool_filter`（all / only / except）、`system_prompt_override`（可空）、`expected_output`（可空）。
  - `body_path` 指向 `skill.md` 本身；**0.12-beta 的 runtime 不读取 body**（全库只有类型定义与 loader 赋值，没有消费者）——这是一个已确认的 SDK 缺口，par-code 必须自己在命令调用时读取正文。
- `Runtime.register_skill` / `list_skills` / `Runtime.invoke ~skills:[id]` 已可用；`compute_active_skill_effects` 会按 `trigger` 自动激活 Auto/Keyword，Manual 只在显式 `~skills` 时生效。
- par-code 目前只注册 `Builtin_skills.builtin_skills`（4 个内置），**没有调用 `Skill_loader.discover`**；用户 skill 目录实际处于"文件存在但不可见"的状态。

### 1.3 REPL 命令层

- slash 命令是 `par_code_repl.ml` 里的硬编码 `match cmd with`（`/help`、`/session`、`/health`、`/reset`、`/checkpoint`、`/checkpoints`、`/quit`、`/cost`、`/plan`、`/build`、`/max`、`/goal`）；未知 `/foo` 会落到模型，而不是"未知命令"。
- `Runtime.invoke` 已有 `?skills : string list option` 与 `?system_prompt_appendix`：前者应用 skill 的 tool_filter/trigger，后者适合注入 skill 正文。两条都在现有调用点未使用。

## 2. 用户可见行为

### 2.1 `/skills` — 查看与重载

```
$ /skills
Custom commands:
  daily-standup   Summarize today's changes and open questions   [project]
  release-check   Run the release checklist before tagging       [user]
Built-in skills: code-reviewer, summarizer, translator, rag-assistant
```

- `/skills reload` 调用 `Skill_loader.force_reload` 后重新 `discover` + `register_skill`，不重启 REPL。
- 与内置 slash 命令同名的 skill 在加载时被拒绝，并显示明确警告（不静默覆盖）。

### 2.2 `/<id>` — 自定义 slash 命令

- 未知 `/foo` 先查 manual skill；命中则把 `/foo` 后面的文本作为本轮 user message，把 skill 正文作为 `system_prompt_appendix`，并 `Runtime.invoke ~skills:["foo"]`。
- 未命中显示 `unknown command: /foo (try /skills)`，不把未知命令悄悄交给模型。
- skill 的 `tool_filter` 生效（例如只读命令只能拿 read/grep/find）；skill 正文只是指令，不执行 shell，正常 turn 的 bash 审批照旧。

### 2.3 `/distill` — 把重复流程写成 skill

```
$ /distill 把"每次改完 OCaml 先跑 dune build、再跑 dune runtest、最后看 git diff"固化成一个命令
→ 分析最近会话/记忆，提出：
   id: ocaml-check
   description: Build, test, then inspect the diff after an OCaml change
   trigger: manual
   body: 1) dune build 2) dune runtest 3) git diff --stat ...
→ 写入 ./.par/skills/ocaml-check/skill.md？
   [y] 写入  [n] 取消  [d] 只看 diff
```

- 先展示完整提案与目标路径；确认后才写文件；已存在同 id 时默认拒绝，`/distill --force` 才覆盖（覆盖前备份旧文件）。
- 写入后调用 `Skill_loader.parse_skill_file` 自验，再 `force_reload` + `register_skill`；成功后提示 `/<id>` 可用。
- 生成内容只包含用户可读的指令，不写入 API key、绝对私人路径或外部项目名。

### 2.4 `/dream` — 记忆整理

```
$ /dream
→ 读取 37 条 project memory
→ 提案：合并 6 组近重复、改写 4 条、剪枝 9 条 usage_count=0 且 >90 天
→ 备份到 ~/.par/backups/memory-20261103-...md
→ 应用？[y/N]（默认 N）
```

- 默认 **dry-run**：只打印合并/改写/剪枝提案与依据，不改 DB。
- `y` 才应用：先 `export_markdown` 备份，再在事务里 `update` / `forget`；失败回滚。
- 不改用户手工条目（`source = Manual`）的正文，除非提案明确引用并再次确认；`prune_stale` 只剪 `usage_count = 0` 且超过阈值的条目。
- 输出一行摘要：`merged 6, updated 4, pruned 9, kept 18`。

## 3. 范围决策记录（R1）

| # | 决策 | 判定 | 理由 / 退役条件 |
|---|---|---|---|
| 1 | v0.9.0 做 self-improvement；**执行级 best-of-N 推迟到 v0.10+** | **已确认**（2026-11-03 用户选择 self-improvement） | README/STRATEGY 已公开承诺 self-improvement；执行级 best-of-N 的退役条件（用户频繁要求"换个实现再来一版"）尚未出现。触发时单开 ROADMAP，先解决 worktree 基线（未提交改动不可见）。 |
| 2 | 自定义 slash 命令 = **manual skill**，复用 SDK `Skill_loader`，不另造命令格式 | **架构正确** | 目录、frontmatter、校验、tool_filter、trigger 都已存在；`/<id>` 是 manual skill 的自然投影。另造格式会与 v0.11.0 的多来源 skill 冲突。 |
| 3 | 用户 skill 默认 **Manual**；Auto/Keyword 需 `skills_auto_activate = true` 显式开启 | **安全默认** | 用户写的 prompt 不应在普通 turn 里静默改变行为；手动命令是显式意图。开启后仍受 tool_filter 限制。 |
| 4 | `/dream` 默认 dry-run；应用前备份 + 事务；不自动删除 Manual 条目 | **安全默认** | 记忆是长期资产；一次坏的合并会污染后续所有会话。备份 + 事务给出可回退路径。 |
| 5 | `/distill` 先提案后落盘；同 id 默认拒绝，`--force` 才覆盖并备份 | **安全默认** | 防止模型覆盖用户手写 skill；路径与内容在确认前可见。 |
| 6 | **par-code 自己读 skill 正文**（`body_path`），以 `~system_prompt_appendix` 注入；同时记录 SDK 缺口 | **范围妥协** | 0.12-beta 的 runtime 不消费 `body_path`；改 PAR 超出项目边界。退役条件：PAR 在 `compute_active_skill_effects` 或 engine 中读取 body 后，删除本地读取。 |
| 7 | 不做远程 skill URL / 自动安装 / skill 市场 | **范围外** | 属于 v0.11.0 Ecosystem；本版只做本地、用户确认的 skill。 |

## 4. 工作项

### W0 — Skill 发现与注册 🔴P0

- `lib/par_code_setup.ml`：启动时 `Skill_loader.discover()`，按 id 注册；项目目录优先；加载失败的 skill 逐条警告（不阻塞启动）。
- 新增 `lib/par_code_skills.ml`（+ `.mli`）：
  - `discover_and_register rt` → `(registered, rejected) result`；
  - `find_manual id` / `list_custom ()` / `reload rt`；
  - `read_body descriptor`（读 `body_path`，去掉 frontmatter，返回 markdown）；
  - `validate_body`（空正文拒绝；≤ N KB，建议 64 KB）。
- 配置：`skills_auto_activate : bool`（默认 false）——**W0/W1 先只注册 Manual；Auto/Keyword 用户 skill 记录为 skipped，配置开关随 W4 补**。`par config set` 支持；旧配置缺字段用默认值。
- 与内置命令冲突的 id 在注册前拒绝，警告包含 id 与冲突对象。

### W1 — 自定义命令与 `/skills` 🔴P0

- `lib/par_code_repl.ml`：slash 分支在硬编码 `match` 的 fallback 前插入：
  - `/skills` → 列表（id / description / project|user / trigger）；
  - `/skills reload` → `force_reload` + 重新注册；
  - 未知 `/foo` → `Par_code_skills.find_manual "foo"`；命中则构造本 turn：
    - `message = 剩余参数（为空时用 skill description 作为默认指令？不：要求参数或提示用法）`；
    - `system_prompt_appendix = Some (existing ^ "\n\n## Skill: <name>\n" ^ body)`；
    - `Runtime.invoke ~skills:["foo"]`；
    - 其余 turn 逻辑（streaming、cost、max 跳过、plan 模式）复用 `execute_turn`，不要让 custom command 绕过安全/计费路径。
  - 未命中 → `render_warning "unknown command ..."`，不调用模型。
- `/help` 增加 `/skills` 与 `/distill`、`/dream` 两行；custom commands 由 `/skills` 列出（避免 help 过长）。
- 参数解析：`/foo a b` → `a b`；引号不特殊处理（与现有 slash 命令一致）；空参数时打印 `usage: /foo <args>` 并提示 skill description。

### W2 — `/distill` 🟡P1

- 新增 `distiller` 辅助 agent（tools-free，`~save:false ~update_current:false`，`invoke_generate`），输入：用户请求 + 最近 N 条记忆摘要 + 当前 skill 列表；输出 JSON：
  `{"id","name","description","trigger":"manual","tool_filter":"all|only:...","body"}`。
- 解析/校验：id 必须 lowercase-hyphen；与内置命令/现有 skill 冲突则拒绝；body 非空且 ≤ 64 KB。
- 目标路径：项目 `.par/skills/<id>/skill.md`（默认）或 `~/.par/skills/<id>/skill.md`（`--user`）；原子写（temp + rename）；`--force` 前备份到 `.par/backups/skills/`。
- 写入前展示 diff/提案；确认后写、`parse_skill_file` 自验、`force_reload` + `register_skill`。
- 测试：临时目录写入 + 解析回读；冲突/空 body/超大 body/覆盖拒绝。

### W3 — `/dream` 🟡P1

- `Par_code_memory` 新增 `update`（包装 `Sqlite_memory.update`）与 `apply_batch`（事务；失败回滚）；`update` 保留 id / created_at / usage_count。
- 新增 `dreamer` 辅助 agent（tools-free），输入：当前 project memory 列表（id/kind/summary/content 截断）+ 最近 checkpoint 摘要；输出 JSON：
  `{"merge":[{"ids":[...],"kind","content","summary","citations"}],"update":[{"id","content","summary"}],"prune":[{"id","reason"}],"notes":"..."}`。
- 应用规则：merge = 新建/更新一条 + forget 其余；update = 改写；prune 只允许 `usage_count = 0` 且 `updated_at` 超过阈值（默认 90 天）；Manual 条目正文不改。
- 默认 dry-run；`/dream apply` 或确认 `y` 才执行；执行前 `export_markdown` 到 `~/.par/backups/memory-<ts>.md`。
- 测试：JSON 解析（缺字段/越界/非 JSON）、dry-run 不改 DB、apply 的合并/剪枝计数、事务失败回滚（可注入坏的 update）。

### W4 — 测试与文档 🟡P1

- 单元：skill 发现/注册/冲突、body 读取、`/<id>` 参数解析、`/skills` 列表、`/distill` 写入/拒绝覆盖、`/dream` 解析/dry-run/apply。
- 集成：REPL `/skills`、未知命令、`/foo` 用 dead endpoint 验证"命令被识别且失败可控"、`/distill`/`/dream` 未确认时不写盘。
- 文档：README（roadmap + 命令）、CHANGES、STRATEGY、DECISIONS（R1 + SDK `body_path` feedback）、AGENTS（新模块/命令）。
- 真机 dogfood（发布前）：真 provider 下 `/distill` 生成一个 skill、`/<id>` 调用它、`/dream` 对 seeded DB 做 dry-run + apply；记录证据。

### W5 — 发布 🔴P0（仅在用户明确说"发布"后）

- 版本 bump 0.9.0（`dune-project` + `test/test_par_code.ml` + 重新生成的 `par_code.opam`）。
- 同步四件套 + AGENTS；打 annotated tag `v0.9.0`；release.yml 三平台。
- 发布门禁：`dune build` / `dune runtest` / integration 全绿 + 真机 dogfood 通过 + 独立 review。

## 5. 风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| skill 正文是 prompt injection 载体 | 中 | 本地用户文件、需确认写入、`tool_filter` 限制、不自动执行 shell；远程 skill 推迟到 v0.11.0 |
| Auto/Keyword 用户 skill 静默改变普通 turn | 中 | 默认 Manual；`skills_auto_activate` 显式开启；开启时 `/skills` 标注 `[auto]` |
| `/dream` 合并错/丢记忆 | 中 | 默认 dry-run；备份 + 事务；Manual 条目正文不改；只剪 usage_count=0 且超期 |
| `/distill` 覆盖手写 skill | 中 | 同 id 拒绝；`--force` + 备份；写入前展示 diff |
| skill id 与内置命令冲突 | 高 | 注册时拒绝并警告；`/skills` 显示冲突原因 |
| 编辑 skill 后未生效 | 中 | `/skills reload`（`force_reload`）；启动时 discover |
| `body_path` 无 SDK 消费者 | 确定 | par-code 自己读；记录 feedback；退役条件见 §3 决策 6 |
| `/dream`/`/distill` 的 LLM 调用增加成本 | 低 | 单次辅助调用；`/cost` 计入？——本版先显示 "auxiliary call" 提示，不计入 turn N；文档说明 |

## 6. 测试与验收

- **单元**：`test/test_par_code_skills.ml`（发现/注册/冲突/body/参数）、`test_par_code_dream.ml`（解析/dry-run/apply/回滚）、`test_par_code_distill.ml`（提案校验/写入/拒绝）。
- **集成**：`test/integration/repl/skills_test.sh`（tmux：`/skills`、未知命令、`/foo` dead endpoint）、`distill_test.sh`（确认前不写盘）。
- **回归**：现有 25 套单测 + 12 个 integration 文件全绿。
- **真机**：`/distill` 生成并调用一个 skill；`/dream` 对 seeded DB dry-run + apply；检查备份文件与摘要计数。
- **验收口径**：用户能在不重启的情况下 `/skills reload` 看到新 skill；`/<id>` 进入正常 turn（streaming/cost/approval）；`/dream` 默认不改 DB；`/distill` 默认不覆盖。

## 7. 执行顺序（建议 wave）

1. **Wave 1**：W0 + W1（skill 发现 + 自定义命令 + `/skills`）——这是最小可用面。
2. **Wave 2**：W3（`/dream`）——记忆整理独立于 skill；可先发。
3. **Wave 3**：W2（`/distill`）——依赖 W0/W1 的注册与改写路径。
4. **Wave 4**：W4 + W5（测试/文档/发布）。

> 注：Wave 2/3 可交换；`/distill` 的产品价值更高，若时间有限先做 W2、`/dream` 后置。
