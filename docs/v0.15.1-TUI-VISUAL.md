# TUI 视觉层计划（v0.15.1 起）

> 冻结于 2026-11-18。本文件是本轮视觉工作的验收基线：阶段、判据、回滚都写在这里，实施按阶段推进。

## 目标

让 `par` 的整屏界面在真机终端上「像个成品」：层次清楚（谁在说话、哪段是工具输出、哪段是代码）、节奏稳定（行距、留白、缩进一致）、状态可读（状态栏、模态、进度条一眼能认），并且窄到 60 列、宽到 200 列都不塌。

## 非目标

- 不改交互模型（键位、命令、模态流程保持现状）。
- 不引入主题系统 / 配色配置项（先有一套打磨好的默认配色）。
- 不做鼠标选中、剪贴板、图片协议等终端能力扩展。

## 判据（每个阶段结束必须满足）

1. 真机手机上单手可读：60 列时正文不被截断、不出现字面转义符、不出现花屏。
2. 60 / 80 / 120 列三种宽度下帧结构都不塌（输入行、状态栏、转写区边界稳定）。
3. 同一屏内文字层级不超过 4 级（正文 / 次要 / 强调 / 工具），且颜色与字重一一对应。
4. tmux 抓帧 + ANSI 抓帧双证据；真机手感由本人在手机上复测确认。

## 阶段

### 阶段 1 —— 视觉基线（本次）

- 建立统一间距与缩进规则：用户行、回答、工具行、代码块、空行节奏。
- 用户输入与模型回答在视觉上区分（前缀 + 缩进 + 字重），工具行降级为次要层。
- 代码块与行内代码有可辨识的底色/前景，不靠颜色猜。
- 状态栏信息密度重排：模型 / 模式 / token / 上下文 / 分支，宽度不足按优先级截断。

验收：三种宽度抓帧；层级不超过 4 级；窄屏不截断正文。

回滚：改动集中在 `par_code_screen.ml` 的帧构造与 `par_code_ui.ml` 的样式取值，回滚即 revert 单个 PR。

### 阶段 2 —— 结构元素

- 转写区右侧滚动指示条（只在内容超出时出现）。**已完成。**
- 状态栏按可用宽度收敛（分支 → 上下文 → token 依次让位，模型名最后截断）。**已完成。**
- 工具调用分组：同一轮内的连续工具行折叠成一块（前 4 + 后 3，中间折成计数）。**已完成。**
- 模态与选择器统一边框、标题位置、按键提示行。**已完成。**

### 阶段 3 —— 动效与反馈

- 运行态：非阻塞的活动行（已有 spinner 的收敛版），不闪烁。
- 提交、错误、取消三种终态各有一致的视觉签名（颜色 + 符号）。
- 计时与耗时只在超过 2 秒时出现。**已完成。**

### 阶段 4 —— 主题与可读性收尾

- 深色/浅色终端都能读的配色（不新增配置项，按终端背景自适应或取中）。
- 参数化行高与留白，手机上（窄 + 高 DPI）单独校一遍。

## 顺序与依赖

阶段 1 必须先做完并冻结配色/间距常量，阶段 2 的元素才有统一语言；阶段 4 依赖前三阶段的元素清单。

## 未决

- 是否需要「紧凑模式」（手机上纵向空间紧张时压缩空行）——等阶段 1 真机复测后决定。
- 浅色终端适配策略（探测背景色 vs 取中灰阶）——阶段 4 前调研。
