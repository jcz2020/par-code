# v0.14.0 — 终端体验重做（冻结计划）

> 状态：**已冻结 2026-11-17**。改动本文件需要新的决策记录。
> 目标版本：v0.14.0。前置：v0.13.0（已发布）。

## 1. 目标与非目标

**目标**：把行式 REPL 换成一个正经的终端应用 —— 固定布局、可滚动历史、弹窗、中文不错位、流式不闪。

**非目标**（明确不做，避免范围膨胀）：

- 不自己实现语法高亮引擎。第一版只做 ANSI 着色的代码块/差异；跨语言高亮留到 v0.14.x，走外部高亮器。
- 不做终端图片/六图（sixel/kitty protocol）。
- 不做 Windows/ConPTY 适配。
- 不做多标签、会话侧边栏 —— 那是产品功能，不在"终端体验"里。

## 2. 技术选型（已实测）

| 候选 | 结论 |
|---|---|
| `notty`（原版） | **不可用**：要求 `ocaml < 4.14`，本项目是 5.4.0 |
| `lambda-term` | **不采用**：绑定 Lwt/React/Zed，与 Eio 并发模型冲突 |
| 翻译 bubbletea/ratatui | **不采用**：3000–5000 行重写，且要自己维护 terminfo/宽度/粘贴 |
| **`notty-community` 0.2.4 + `nottui` 0.5 + `lwd` 0.5** | **采用**：OCaml 5.4 上实测安装成功；提供整帧绘制、按键解析、resize 事件、`Term.fds` |

opencode 的精细度来自 Go 生态的 Bubble Tea + Lipgloss；nottui 在 OCaml 里承担同一角色（Lwd 增量模型 + notty 渲染），因此我们写的是**应用层**，不是基础设施。

## 3. 架构决策

- 渲染：`Nottui` 组件树由 `Lwd` 变量驱动；每帧 `Notty_unix.Term.image` 输出。
- 输入：`Notty_unix.Term.event` 给出已解析事件（按键、`Resize`、`End`）。
- **Eio × notty 的桥**：先用 `Term.fds` 取读 fd，Eio 侧 `await_readable` 后再调 `Term.event`（此时必有数据，不阻塞域）。
  - 若 S0 证明该路径不可行，退路是**独立 Domain 跑 UI 循环 + 队列**，Eio 只投递状态更新。二者在 S0 结束时必须落下结论并记入本文件。

### S0 结论（2026-11-17，已验）

**采用 fd 就绪检查，不用 `Term.pending` 单独判断。** `spike/s0.ml` 实测：

- `Term.pending` 只报告**已解析**的事件；原始字节停在 fd 里没被读，所以单靠它永远拿不到按键（第一版就是因此 `last key` 一直为空）。
- 正确做法：`let read_fd, _ = Term.fds term` + `Unix.select [read_fd] [] [] 0.0`（或 Eio 的 `await_readable`）判断可读，再调 `Term.event`。
- 验收结果：120×40 与 80×24 均正确显示；中文/emoji 行完整（notty-community 带 uucp 宽度）；按键 `j` 被捕获（`last key: j`）；`tmux resize-window` 后 `size: 90x30`、`resizes: 1`；`q` 退出后 shell 提示符与 `BACK-FROM-APP-0` 正常出现（alt-screen 已释放）。
- 因此**不需要**独立 Domain + 队列的退路；单线程 UI 循环（轮询可读 + 渲染）已够，agent 的 Eio fiber 只需把状态写进受保护的 cell。
- 弹窗：`prompt_confirm` 由"同步读 /dev/tty"改为"投递请求 + `Eio.Promise` 等待"，由 UI 循环服务。调用点三处（bash 审批、`/distill` 确认、plan 工具确认）。

## 4. 阶段与验收

每个阶段独立可回滚；**下一阶段不得在上一阶段验收前开始**。

### S0 —— 桥的可行性（0.5–1 天）

做：一个最小 demo —— 进 alt-screen、画一帧（含状态栏）、读一个按键、退出恢复。
验收：
1. tmux 中 120×40 与 80×24 两种尺寸下都正确显示；
2. 中文与 emoji 对齐（列宽用 uucp 校对）；
3. 按键能读到（`q` 退出）；
4. 退出后终端恢复正常（光标、alt-screen、回显）。
产出：结论写入 §3（走 fds 还是 Domain）。

### S1 —— 会话渲染（2–3 天）

做：把"消息列表 / 流式回复 / 工具行 / markdown"建模成 Lwd，复用现有 `Par_code_ui` 的 image 生成逻辑。
验收：
1. 一轮对话（含流式与工具调用）在框内渲染，无闪烁；
2. `Par_code_ui.render_*` 的调用点全部走新路径，旧的 stdout 直写仅保留在 `ui = "line"` 分支；
3. 超长输出不撑爆布局（截断 + 折叠标记）。

**进度**：S1a 完成（2026-11-17）—— `par_code_screen` 落地：alt-screen、转录缓冲、流式 `feed`/`end_line`、状态栏、j/k/PgUp/PgDn 滚动；`Par_code_ui.lines` 提供结构化访问，`attr_of_style` 完成到 Notty 的样式映射。实测 100×24：中文列对齐、状态栏从 `streaming 3/13` 走到 `done`、`k` 正确回看历史。
**S1b 完成（2026-11-17）**：`create_screen_backend ~sink` 让所有 `render_*` 调用点无需改动就落进帧内；`append_truncated` 单图上限 60 行并附 `… (N more lines)`；**转录按行存**（此前按图片存，多行图片算一条，导致分页错位——实测 `lines=66` 才对）。
**S1 遗留**：REPL 主循环尚未跑在帧内（输入仍走 linenoise），属 S2 范畴。

### S2 —— 输入行（1–2 天）

**进度（2026-11-17）**：输入层完成 —— 光标移动、退格/删除、Ctrl-A/E/U/K/W、历史上下翻、Tab 补全（多候选走公共前缀）、UTF-8 输入；`read_line` 以`Some line`/`None` 交付，空串表示取消。实测：`/hel`+Tab → `/help`；Up 取回上一条；Enter 提交后进入转录。
**未验**：Ctrl-C 在编辑模式下的取消（notty 对 0x03 的投递方式待查），以及多候选时的候选列表展示（现在只补公共前缀）。

做：nottui 输入组件 + 历史 + Tab 补全（复用 `Par_code_ui.commands` 与技能/流程候选）。
验收：
1. 方向键、Home/End、Ctrl-A/E/U/K/W、退格/删除正确；
2. 历史上下翻、`/he<TAB>` → `/help`；
3. 粘贴多行不炸（bracketed paste 或逐字符降级）；
4. 纯 buffer 逻辑有单测（不依赖终端）。

### S3 —— 弹窗（1–2 天）

做：三处 `prompt_confirm` 改 Promise 版；审批块用居中方框渲染。
验收：
1. 回合进行中弹出审批，答 `y` 后 agent 继续，答 `n` 后被拒；
2. `/distill` 确认、plan 工具确认同样可用；
3. 无人应答时可用 Esc 拒绝（不挂死）。

### S4 —— 打磨与收尾（2–3 天）

做：状态栏（模型/模式/令牌/花费/git 分支）、主题、鼠标滚动、resize 重排、错误提示样式。
验收（**8 条手感清单，全绿才算完**）：
1. 全屏稳定；2. 固定状态栏；3. 可滚动历史；4. 弹窗可用；5. 中文不错位；6. 不闪不撕裂；7. 粘贴正常；8. resize 不崩。

## 5. 回滚

- 配置项 `ui = "tui" | "line"`，**默认 `line`**；S4 验收通过后才翻转默认。
- 非 TTY（管道、CI）强制 `line`。
- 每个阶段一个提交系列，回退即 revert 该系列；v0.13.0 tag 是安全基线。

## 6. 已知风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| notty 的阻塞 `Term.event` 与 Eio 相性 | 整个方案 | S0 先验；Domain 方案兜底 |
| 弹窗在 handler 内同步阻塞 | 架构 | S3 提前到 S1 之前做（若 S0 结论指向同步模型） |
| 终端差异（Termux / proot） | 体验 | S0 就在两种尺寸 + Termux 下验 |
| 范围膨胀（想去追 opencode 每个细节） | 工期 | §1 非目标 + 8 条清单作为唯一验收 |
